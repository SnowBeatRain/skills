# Liquid Glass：光学、运动与层级

先读 [官方定义](official-liquid-glass.md)。目标是让使用者看出透明控件对背后内容的光学影响，并通过连续运动理解状态关系。

## 1. 什么决定“像不像”

| 必要判断 | 正确表现 | 不能替代它的东西 |
|---|---|---|
| 透镜感 | 背景线条/纹理在边缘弯折，内部仍可辨认 | 单纯 blur、描边、白色径向光 |
| 厚度线索 | 高光沿几何边缘变化，背后内容决定观察到的效果 | 固定整块白渐变、堆叠厚阴影 |
| 连续性 | 一个控件以连续几何变为另一个状态 | 隐藏旧卡片并淡入新卡片 |
| 功能层级 | 导航/工具浮在内容之上 | 整页玻璃内容面板 |
| 可读性 | 原生适应或经过验证的 Web 局部前景处理 | 为所有控件强加厚白/厚黑遮罩 |

本包 WebGL 示例使用圆角矩形距离场构建透镜边缘，再对同一个背景纹理做位移采样；它是可检查的光学近似，不是完整物理光线追踪。不能给一个完全没有位移的 basic 模板换个名字当作光学实现。

## 2. 素净与透光可以共存

默认黑白灰，不需要红紫蓝背景。选择能显示光学变化的灰阶照片、文字、细线、纹理或实际应用内容；校准时用网格和轮廓线。纯色或极缓慢渐变几乎没有可观察细节，会掩盖折射是否存在。

演示先保留参考图案，确认折射开/关差异，再换成产品内容。若产品背景实际均匀，接受材质表现较弱，不为了制造“玻璃感”添加霓虹、光球或循环背景动画。

## 3. 背景、光学与内容分层

```text
受控背景纹理（真实采样源，变化时同步上传）
→ 光学画布（重采样背景 + 边缘/光反馈）
→ 真实 DOM 功能控件（不模糊文字，保留键盘/读屏）
```

同一屏目标 1–3 个关键玻璃区域，避免重叠；四个是本渲染器的硬容量，不是设计目标。普通卡片、图表、正文继续用标准材质。

圆角跟随控件几何：药丸使用半高，面板用对应尺度的连续圆角近似。Web border-radius 不是原生连续曲率，不能靠固定 24/28/32px 声称“官方圆角”。

## 4. 可读性

Regular 的原生自适应与 Web 手工处理是不同能力。Web 先控制背景、前景颜色和文字布局，再按必要范围添加局部衬底；不要把遮罩铺满整个透镜。

旧版方案曾在 .14 的白底上叠 .56 的白遮罩，合成白色填充在高光之前已约 .622；这会显著降低透光。深色 .80 的全区域遮罩同样容易变成实底面板。旧资源只作为 basic 兼容，不能复制进新的光学层。

正文与背景最终对比度 ≥4.5:1，大字 ≥3:1。对比度不够时可以局部增加覆盖，但若为此失去全部透光，就应把该内容改为标准材质，而非继续宣称光学目标已达标。

## 5. 动效

几何状态使用同一透镜 ID/实例，不在过渡中切换成不相关截图。导航选中态平移、按钮展开保持连续的边界与采样。采用可打断的弹簧或时间曲线，不持续摆动。

本包示例在输入期间/收敛期间更新参数；结束后停止 rAF。DOM 文档流尺寸在布局变化时确定，动画仅使用 transform/opacity 与画布几何，不逐帧重排。减少动态时直接切换目标几何，保留静态折射。

真正的多物体流体融合需要相应原生容器、距离场合并或更复杂的渲染。本包独立透镜渲染器不提供自动融合，不能让透镜重叠后声称已经实现。
