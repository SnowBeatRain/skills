# 可复用提示词

仅在用户要求生成/复用提示词时读取。选择一个模板，按现有上下文填好变量；普通执行不必先生成提示词文档。

## 新建页面

```text
参考 apple-design，为【业务场景】在【项目/技术栈】实现界面。
主任务是【任务】，效果目标为【普通风格/标准毛玻璃/原生材质/Web 光学】，作用范围为【局部/网页视口】。
沿用现有组件和品牌；场景范围与控件宽度分别设计。
光学来源必须与显示背景一致，操作保留真实语义和降级。
直接完成实现，验证相关视口、状态和操作，给出入口、实际结果及未测项。
```

## 扩展到全屏

```text
把【现有区域】扩展到整个网页视口，保留已认可的【内容、材质与交互】。
检查祖先限宽/裁切和坐标，让背景与光学输出覆盖同一范围；分别安排功能控件的宽度。
不自动调用 Fullscreen API，不把正文全部玻璃化，不用无关纹理替换真实背景。
实施后核对覆盖、裁切、几何、短屏可达性及未测项。
```

## 精修组件

```text
保留【已认可部分】，只调整【目标组件】的比例与样式。
按内容、分组和可用空间决定宽度；同组高度/密度一致不等于必须等宽。
保留热区、长标签和动态选项，减少重复胶囊但保留对比度保护。
沿用现有组件，局部修正冲突样式；几何变化同步材质，选中底板测量实际项目。
直接实施并验证受影响范围，不重建已认可页面。
```

## 复用分析

```text
只读分析【项目】实际值得复用的界面能力，不改文件。
按调用点、差异和已有组件库说明候选职责、接口方向及成本。
区分现成 API 与建议组件；相同颜色间距先复用 Tokens，不为凑清单设计万能组件。
```

## 实施提取

```text
在【项目】按既有架构提取【明确重复的能力】，并更新原调用点。
先检查已有组件，简述接口后直接实施；业务数据、文案和持久化不埋入视觉基础。
不写死选项数、全局 ID 或坐标；验证多实例、生命周期、焦点、布局与适用的工程检查。
报告实际修改和未测项，不停在组件清单，也不无关重构或升级依赖。
```
