舞台内的内容（彩色卡片、图片、文字）位于玻璃之下。工具条与卡片悬浮在上方，向下滚动时，你可以看到背景内容从玻璃的模糊区域中穿过——这就是 Liquid Glass 的"动态感与景深感"。

工具条使用通透的 CSS 配方与 38% 暗色底。HIG 对原生 Clear 提到的 35% 只是亮背景下的参考，不能保证所有文字对比度；此处也不是官方 Clear 组件。

说明面板采用较强模糊，以展示易读性与透光之间的取舍。实际业务中不要把所有内容卡片都玻璃化。

02 · 变体对比

同一张背景，两种取舍

选型依据只有一个问题：当前最重要的是"易读性"还是"内容可见性"？两块玻璃悬浮在同一背景上，各自采用一个变体。

文本类组件适用

Regular 思路 · CSS 近似

模糊与亮度处理偏重文本易读；在实际背景上仍需核验字号和合成对比度。

媒体控制适用

Clear 思路 · CSS 近似

较高透光度 + 38% 暗色底，演示内容可见性的取舍；前景仍需按实际背景检查对比度。

两种变体的选择逻辑

原生 Regular 偏重文字易读，Clear 用于富媒体背景。本页通过手动主题切换调整颜色，并未自动感知控件后方的局部亮度。

03 · 颜色规则

色彩是稀有资源：只强调最重要的那一个

Liquid Glass 默认没有固有颜色，直接采用后方内容的颜色。主要操作可用背景强调色，选中标签和状态符号也可用色；避免同时强调过多控件。

单色方案 收藏 关注

正确示范：一个强调色

强调色只给"主要操作（关注）"的背景；"收藏"保持单色半透明。界面上只有一个视觉焦点。

✕ 避免
多个强调色 收藏 关注

错误示范：到处都是重点

两个按钮都上了高饱和色，界面"发花"、没有主次。Apple 明确要求避免为多个控件背景加色。

04 · 使用要点

使用材质时的六点提醒

以下综合了材质建议与本例的设计取舍，具体使用仍以平台、内容和实际可读性为准。

规则一

不要进入内容层

玻璃只用于控制/导览功能层；App 背景等内容层用标准材质。唯一例外：内容层里的滑块、开关等瞬态交互元素。

规则二

谨慎使用，克制优先

系统组件自动采用；自定义控制上只用于最重要的功能元素。过度使用会干扰内容——而"把注意力引向内容"恰是它的初衷。

规则三

按场景选变体

文本多、背景复杂用 regular（易读）；悬浮于照片/视频上用 clear（内容可见）。选型只问：易读性还是内容可见性？

规则四

透明变体配暗层

Clear 在亮背景下可考虑约 35% 暗层；背景够暗或媒体控制已有暗层时不重复添加。最终对比度仍须核验。

规则五

前景用安全颜色

玻璃上的文字/符号用对比度安全色或系统虚化颜色，不要硬编码浅灰（systemGray3 在材质上对比度不足）。

规则六

尊重系统设置

降低透明度、提高对比度、深色模式、Liquid Glass 首选外观都会改变渲染。页面永远要准备降级方案——就像本页的"降低透明度"开关。
